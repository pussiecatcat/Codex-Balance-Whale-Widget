# Codex 小龙娘 界面与产品整改方案

日期：2026-11-05　基线：`feat/bubble-editor-port`（PR #33，提交 `2534160`，已包含 PR #32）　配套样稿：[`DESIGN-REMEDIATION-mockups.png`](DESIGN-REMEDIATION-mockups.png)

## 0. 结论与执行方式

**结论：**上一轮只统一了配色和控件，没有还原原版的字体和气泡内容结构，也没有处理菜单和设置的信息结构，所以看起来素、结构怪。要做的是一次产品级整改，而不是继续微调 CSS。

**执行顺序：**

| 顺序 | 工作包 | 优先级 | 主要文件 | 依赖 |
| --- | --- | --- | --- | --- |
| 1 | WP1 视觉基础与字体 | P0 | `whale-widget.css`、`ui.css`、`settings.css` | 无 |
| 2 | WP2 气泡 | P0 | `default-content.js`、`bubble-rows-view.js`、`render.js`、`quota.js` | WP1 |
| 3 | WP3 日常菜单 | P0 | `whale-widget.js`、`insights.js`、`workshop.js`、`account-view.js` | WP1 |
| 4 | WP4 设置窗口 | P0 | `main.cjs`、`settings*.{html,css,js}`、`settings-catalog.js` | WP1 |
| 5 | WP5 气泡编辑器 | P0 | `bubble-editor-view.js`、`bubble-advance-control.js`、`bubble-editor-controller.js` | WP1 |
| 6 | WP6 统一命名 | P1 | 全部界面文案 | WP3、WP4、WP5 |
| 7 | WP7 其余界面 | P1～P2 | 记账、API 弹窗、记录窗口等 | WP1 |

每个工作包单独开 PR。WP2 到 WP5 改动的文件基本不重叠，可以并行；`assets/whale-widget.js` 和 `whale-widget.css` 是共同冲突点，后合并的 PR 需要变基。

**执行前必读：** `CLAUDE.md`、`docs/DASHBOARD-B.md`、`docs/OUTSIDE-CLICK-DECISION.md`、`docs/V0.3-PLAN-AND-PROVENANCE.md`。

**必须遵守的约束：**

- 只做中文界面。不引入 UI 框架或渲染层构建系统。
- 菜单保持紧凑，不做三页式大面板，也不做点击空白关闭。
- 订阅额度、API 余额、本机观测 token 必须分开。金额继续写「已观测」，不要因为参考图写的是「今日已用」就改回去。
- 按 `CLAUDE.md`，提供商名称不得出现在界面上，所以默认标题用「当前 API 余额」，不用参考图的「DeepSeek 余额」。
- 不删除任何现有功能。下文的「移除」指移除重复入口，功能仍保留在指定位置。

**每个 PR 的完成标准：**

1. `npm run verify` 通过。
2. 在 Windows 上运行 `node tests/settings-window-smoke.mjs` 和气泡视觉测试 `tests/bubble-visual.mjs`。
3. PR 附修改前后的 Windows 实机截图，并与样稿对照。

本方案的代码判断来自读源码和静态渲染。方案作者的环境无法运行 Electron，所有实机效果都需要执行者确认。

## 2. 设计规范

### 2.1 视觉语言

原版的辨识度来自四点：深蓝描边和半透明深蓝底、等宽数字、靛蓝渐变大数字、彩色小标签。整改后所有界面都使用这一套，同时比上一轮多一层卡片层次。

| 名称 | 值 | 用途 |
| --- | --- | --- |
| `ink` | `#203170` | 主文字、主按钮、气泡描边 |
| `ink-hover` | `#2f4488` | 主按钮悬停 |
| `blue` | `#536ba9` | 气泡正文 |
| `muted` | `#5a6a92` | 说明文字，白底对比度达到 AA |
| `pale` | `#8497c9` | 气泡内次要数字（大字号） |
| `tint` / `tint-strong` | `rgba(32,49,112,.08)` / `.14` | 次要按钮、选择框、选中态 |
| `edge` / `hair` | `rgba(32,49,112,.4)` / `.14` | 控件描边 / 分隔线 |
| `wash` | `#f4f6fb` | 设置窗口背景 |
| `card-head` | `#f8fafd` | 卡片标题栏背景 |
| `indigo-gradient` | 现有 `.dshwv-rgb-indigo` | 气泡大数字、窗口标题 |
| `ok` / `warn` / `danger` | `#2fa24c` / `#b97a24` / `#c0392b` | 状态文字和标签 |

| 元素 | 规格 |
| --- | --- |
| 字体：数字与气泡 | `Consolas, "Microsoft YaHei UI", "Microsoft YaHei", monospace`；开启 `tabular-nums` |
| 字体：界面文字 | `"Microsoft YaHei UI", "Microsoft YaHei", sans-serif` |
| 字号 | 窗口标题 15；卡片标题 13 粗体；字段名 13 半粗；说明 11.5；菜单 12 |
| 圆角 | 控件 6、卡片 11、弹窗 13、菜单 10 |
| 控件高度 | 菜单 26、设置窗口 28、窗口底部按钮 30 |
| 卡片 | 白底，`1px rgba(32,49,112,.2)`，`0 3px 10px rgba(32,49,112,.07)`，带 34px 标题栏 |
| 按钮 | 主操作深蓝实底；次要操作 tint 底加 edge 描边；添加类虚线描边 |
| 图标 | 全部用同一套线性 SVG（16×16，描边 1.8）。替换文字符号 `⠿ ✕ ↑ ↓ ☰ ▸ ▾` |

`CSS_HEX_BUDGET` 必须等于实际颜色数，测试为严格相等。新增颜色前先复用现有值，否则要同步修改预算。

### 2.2 气泡内容结构

样稿 A、B。气泡统一为四行：

| 行 | 原版模块 | API 余额模式 | 订阅额度模式 |
| --- | --- | --- | --- |

### WP5 气泡编辑器（P0）

样稿 E。

**合并难用的原因（读代码得出）：**

- 合并只能靠拖拽，界面上没有任何文字提示，只在原生悬停提示里写了一句。
- 第 1 条不能参与合并（`from < 1`、`to < 1` 直接返回），只有 1 条「再次点击」时就没有可合并的目标，图六正是这种情况。
- 用户看到的「A/B」也没有解释。
- 拖拽判定区依赖内容按钮的矩形，上下边缘是排序区，容易落错。PR #33 改善了这点，但还是拖拽方案。

**改法：**

1. **增加「二选一」按钮。** 每条普通内容都有这个按钮：如果下一条是普通内容，调用现有的 `pairBubbleSteps(items, index + 1, index, 'pairR')` 合并；如果没有下一条，先新建一条默认内容再合并。拖拽保留作为进阶方式。
2. **A/B 显示。** 改称「随机二选一」，显示为 `A · 内容摘要 | 10 : 1 出现比例 | B · 内容摘要 | 拆开`。比例输入沿用 PR #33 的立即写入逻辑。
