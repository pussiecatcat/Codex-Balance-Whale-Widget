# 重构阶段 4–5 验收记录

验收日期：2026-10-10。实施分支：`codex/refactor-sound-settings-boundaries`。

## 1. 阶段 4：前端主体分解

本轮把气泡内容、队列、场景、编辑器模型与命令、用量视图、角色管理、人物交互、菜单命中、任务结束音效和轮次通知轮询拆成可独立导入的模块。`assets/whale-widget.js` 继续承担现有 DOM 的装配和兼容适配，迁出的实现已从入口删除。

直接模块测试已经替代本轮涉及的源码截取测试，包括轮次轮询、气泡内容、任务结束音效、用量概览、模型汇总和输入命中策略。剩余源码截取测试只覆盖尚未进入本轮拆分范围的平台生命周期兼容代码，删除这些适配器属于阶段 6。

| 维护指标 | 重构基线 | 当前值 | 持续门槛 |

## 2. 阶段 5：服务编排与平台边界

`WhaleService` 保留为兼容门面，内部职责已经分到以下组件：

- `BalanceQuery`：余额缓存、并发查询、强制刷新排队和活动账户范围。
- `TurnAccounting`：轮次状态、父子任务归并、结算、恢复记录和账本写入。
- `NoticePublisher`：通知序列、延迟发布、取消修正和最后一轮只读快照。
- `session-events.mjs`：实时与历史读取共享的事件解码、计数规范化、计数器差分和时间戳规则。

`SessionMonitor` 只读取 `WhaleService.monitorStatus()` 返回的分离 DTO，不再读取活动轮次或恢复日志对象。宿主初始状态和后续状态都经过 `host-state.cjs` 的同一白名单适配，未知字段不会进入窗口控制状态。

发行包检查显式包含上述组件和会话模块。新增的同源样本测试把相同 JSONL 记录分别送入 `SessionParser` 与 `InsightAccumulator`，验证输入、输出、缓存输入和推理输出计数一致；历史扫描测试同时覆盖 `sessions`、`archived_sessions`、文件数量预算、字节预算和 `complete=false` 语义。

## 3. 验证结果

以下命令构成阶段 4–5 的合并门槛：

```text
npm test
npm run check:package
npm run check:architecture
npm run test:desktop
python scripts/build-release.py
```

Windows 真实 Electron 审计覆盖 20 项场景，包括角色回退、GIF/APNG 命中、拖拽与穿透、气泡编辑、用量与额度刷新、账户切换、资源管理、音效设置保存/取消、模式切换、窗口复位和关闭流程。

本轮完整 Node 测试结果为 320 项通过、0 项失败；Windows 真实 Electron 审计为 20 项通过、0 项失败。

macOS 相关状态转换、配置保护和平台分支由自动测试覆盖；本轮没有 macOS 实机，因此 macOS 跟随、最小化恢复和透明窗口输入的实机验收仍需在发布前执行。此限制不影响 Windows 验收结论。
