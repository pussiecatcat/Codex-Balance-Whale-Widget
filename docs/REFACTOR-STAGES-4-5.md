## 本轮审阅问题的处理

| 问题 | 修复与验证方式 |
| --- | --- |
| 结算日志先删除，发布失败后没有可靠重试 | 通知意图与账本同次写入；内存重试每 2 秒执行，启动及账户切换读取未确认的意图；结算日志清理失败也进入通知队列。覆盖真实结算、写盘故障、确认失败和进程重建。 |

### 通知恢复的行为约定

这是“最新任务状态”的恢复机制。只恢复当前账户、带新通知意图标记且请求时间未超过 5 分钟的记录；升级前的历史账本不会集中弹出通知。新任务已开始时，旧任务延迟的高负载失败提示会被抑制。更旧的重试不会替换较新的状态。UI 播放音效不具备跨进程的严格恰好一次保证。

### 2026-10-24：功能依赖与生命周期收尾

- 8 个已拆出的功能模块不再读取 `window.Whale*`。模型与额度文本、绑定、模型选择、订阅通知、反馈音效、选择框增强和短时渲染均由装配入口传入操作；运行时模式和后加载的服务仍在调用时读取。
- 音效启动与经典脚本就绪握手集中到 `desktop/ui/app/sound-settings.js`。控制器接收预览播放器、选择框和渲染接口；已取消的启动不会挂载菜单。
- 任务轮询拥有 AbortSignal 与 dispose，关闭时清除入口定时器；测试覆盖响应返回前和 JSON 解析期间关闭，均不写入游标、不发通知、不播放声音。
- 备用 Audio 实例由任务音效功能持有，在结束、失败和销毁时释放。松开音效只在按下播放结束且功能仍存活时创建；迟到结束回调不会重新播放。
- 气泡预览重建前清理金额、额度及模型绑定，避免留下脱离 DOM 的旧绑定。
- 全局读取白名单已清空，门禁也检查裸全局变量、解构别名和指向应用适配器的反向导入。保留的 11 个兼容全局接口仍由经典脚本使用；不把“功能模块零隐式读取”等同于整个应用已消除全局状态。

## 验证与限制

完整门槛：

```text
npm run verify
node tests/desktop-audit-smoke.mjs <隔离输出目录>
```

`verify` 包含 ESLint、全部 Node 测试、包依赖、架构门禁和发布包构建（包括归档完整性、隐私与文档链接检查）。Windows Electron 审计覆盖 20 项真实交互：角色回退、APNG、鼠标命中、气泡编辑、额度故障恢复、音效设置、资源管理、模式切换、窗口复位和关闭等。

最终完整验证为 **540 项 Node 测试通过，0 失败、0 跳过**；合入最新主分支后，**20 项 Electron 检查通过**。ESLint、包依赖、架构门禁、发布包构建、归档完整性、隐私扫描及 113 个文档链接检查均通过。测试使用隔离数据，不依赖用户真实账户余额。
