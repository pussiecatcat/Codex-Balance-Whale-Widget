## 本轮审阅问题的处理

| 问题 | 修复与验证方式 |
| --- | --- |
| 结算日志先删除，发布失败后没有可靠重试 | 通知意图与账本同次写入；内存重试每 2 秒执行，启动及账户切换读取未确认的意图；结算日志清理失败也进入通知队列。覆盖真实结算、写盘故障、确认失败和进程重建。 |
| A 确认失败、B 已发布后，A 重试覆盖 B | 持久化顺序号与发布回执使重试幂等；旧状态只确认账本，不增加通知序列。单条确认失败不阻塞后续通知。 |
| 拖动/单项设置提交整份配置；不同事件互相冲突 | 位置保存与设置保存分开；设置队列捕获每次操作意图，按叶字段生成 base/patch；服务端逐叶比较，数组作为完整值处理；同字段 409 交给界面展示，不静默刷新后覆盖。 |
| 编辑器实现与临时状态集中在入口 | 角色导入和裁剪迁入 roles，音频编辑/预览/裁剪迁入 audio，气泡序列/模块/提醒编辑迁入 bubble；气泡草稿只在编辑器内部修改。 |
| 销毁后全局监听、预览和迟到回调继续运行 | 角色、选择器、交互与新增编辑器提供 dispose；释放监听、计时器、预览和浮层；异步完成检查生命周期；动态音频列表释放跑马灯，选择器以弱引用追踪控件。 |
| 全部模块位于 widget，正则门禁不能表达真实边界 | 按 roles/audio/bubble/usage/character/resources/sound-settings 分目录；公共控件进入 components，请求及设置进入 services；语法/作用域分析识别静态、动态、重导出和副作用导入，以及网络别名和全局存储。 |
| 资源路由保留模拟 req/res 响应收集 | handler 直接返回 `{status, headers, body}`；dispatcher 负责请求大小、方法、退役字段过滤和 HEAD，原 URL 保留。 |
| 资产请求错误处理与 CI 门禁不一致 | asset-client 使用 requestJson，覆盖 HTTP/业务/取消错误；CI 增加 check:package。 |
| 文档完成状态高于实际实现 | 下文明确已完成的功能边界与后续目标；历史规模数据不再当作当前值。 |

### 通知恢复的行为约定

这是“最新任务状态”的恢复机制。只恢复当前账户、带新通知意图标记且请求时间未超过 5 分钟的记录；升级前的历史账本不会集中弹出通知。新任务已开始时，旧任务延迟的高负载失败提示会被抑制。更旧的重试不会替换较新的状态。UI 播放音效不具备跨进程的严格恰好一次保证。

## 验证与限制

完整门槛：

```text
npm run verify
node tests/desktop-audit-smoke.mjs <隔离输出目录>
```

`verify` 包含 ESLint、全部 Node 测试、包依赖、架构门禁和发布包构建（包括归档完整性、隐私与文档链接检查）。Windows Electron 审计覆盖 20 项真实交互：角色回退、APNG、鼠标命中、气泡编辑、额度故障恢复、音效设置、资源管理、模式切换、窗口复位和关闭等。

此前一次完整验证为 518 项 Node 测试及 20 项 Electron 检查通过；复核补充了通知日志清理故障和菜单销毁用例，最终结果记录在 PR。测试使用隔离数据，不依赖用户真实账户余额。

本轮未进行 macOS 实机验收、长期内存/CPU 基准，以及发行包安装→更新→回滚的完整实机演练。构建仍是 PR 候选版，不是完成所有平台发布验收的正式版本。
